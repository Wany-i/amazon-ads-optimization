# 一站式信息聚合项目评估与单入口集成方案

评估日期：2026-09-21 · 星标与活跃度为当日 GitHub 实测

---

## 一、结论先行

1. **没有单一项目能同时做到「覆盖全 + 免授权 + 免维护」。** 覆盖越广，越依赖登录态；越免授权，越偏新闻/热榜。
2. **按授权成本排序（你要的最优形态在最上面）**：
   - 真正的「装完即用、永不重授权」只有 **热榜/趋势 + 新闻 + RSS + 网页读取 + 元搜索** 这一类。
   - **worldmonitor / AIHOT** 属这一档：装完即用。worldmonitor 免费档 `tools/list` 公开，AIHOT 完全匿名只读。
   - **Agent-Reach** 是一半 L0、一半 L2：6 个渠道零配置，**小红书/Twitter/Reddit/FB/IG 必须登录态**，Cookie 会过期。
   - **last30days 系列**属「装一次跑一次」，但用本地浏览器抓取，平台改版就要等作者跟进。
   - **最重的是 MediaCrawler / 小红书 MCP / 公众号逆向**：需扫码或 Cookie，**会过期、有封号风险**。
3. **封号风险的真实分布**：只读公开聚合（热榜/AIHOT/RSS）= 无风险；复用你自己的浏览器会话 = 低（但可能触发验证码/限流）；服务端 IP 批量抓取 + 账号 Cookie = **高**，尤其小红书、抖音、公众号。
4. **单入口的正确做法不是「写个爬虫包打天下」，而是分层路由**：L0 自带实现、L1/L2 指向成熟工具，并把授权成本讲清楚。已交付为 `info-hub` Skill。

## 二、四个重点项目的评估

### 1. worldmonitor — [koala73/worldmonitor](https://github.com/koala73/worldmonitor) ★87.1k AGPL-3.0

**是什么**：全球情报仪表盘。新闻聚合 + 地缘政治监测 + 基建追踪 + 财经雷达（股/商品/加密）+ 国家不稳定指数 CII，六套站点变体，Tauri 桌面端。

**优势**
- 接入面最全：REST `https://api.worldmonitor.app`（有 OpenAPI）、**MCP `https://worldmonitor.app/mcp`（Streamable HTTP）**、npm CLI `npx worldmonitor`、Python/Go SDK、Ruby gem、桌面二进制。
- 自带 MCP + Agent Skills 扩展，天然是「Agent 可读」。
- 可完全本地跑（Ollama），**零 API Key** 启动。

**局限**
- `tools/list` 公开但 **`tools/call` 需要 `X-WorldMonitor-Key` 或 OAuth** —— 即访问数据要注册拿 key。
- 部分数据源仍需自带凭证（见 `.env.example`）。
- **几乎不覆盖中文社媒**：没有微博/小红书/抖音/公众号。它是「国际宏观」不是「中文舆论」。
- AGPL-3.0：改造成对外服务需开源。
- 定位是「仪表盘/看板」，**不是关键词级舆情检索**，提问式调研能力弱于 last30days。

**结论**：宏观/地缘/财经情报的最佳单一来源；但和「中文平台选题」是互补而非替代。

### 2. Agent-Reach — [Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach) ★84.0k MIT

**是什么**：一条 CLI 给 Agent 装上网能力，自动替你选接入方式，`agent-reach doctor` 体检每条渠道。

**优势**
- **零配置即用**：网页（Jina Reader）、RSS/Atom、YouTube 字幕、GitHub 公开仓库、B站搜索与详情、V2EX、雪球。
- 不用改代码：接入方式换代由它兜。
- MIT，本地跑，Cookie 不外传，明确声明「不替你登录、不读你的浏览器 Cookie」。

**局限 / 授权成本**
- **小红书、Twitter、Reddit、Facebook、Instagram 必须登录态**：要么 OpenCLI 复用你已登录的 Chrome，要么手导 Cookie。**这就是你要避开的「定期授权」**。
- Reddit 已无零配置路径（匿名接口被封）。
- 它是**编排层**，底层各渠道的稳定性和平台反爬决定成败；上游一变它就报错（好在有 doctor）。

**结论**：目前「一站式」里工程完成度与诚实度最好的一档。**建议只启用它的 L0 渠道**，L2 交给专用工具。

### 3. last30days（含中文版）

- 上游：[mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill) ★62.5k MIT —— 近 30 天跨 Reddit/X/YouTube/HN/Polymarket/全网的研究综述。
- 中文版：[Jesseovo/last30days-skill-cn](https://github.com/Jesseovo/last30days-skill-cn) ★1.8k —— 中国 8 大平台近 30 天，v3.2 用 Playwright + 公开搜索兜底，含 `--diagnose` 自检与 HTML 报告。

**优势**
- 唯一把「**时间窗 + 跨平台 + 出报告**」做成一条命令的方案，正好补 hotlist 缺的历史纵深与归因。
- 中文版单入口 `last30days.py`，`--as-of` 可回溯，零硬依赖可降级运行。

**局限 / 风险**
- **本质是爬取**：小红书/知乎/抖音靠浏览器抓取，平台改版即失效（README 自己就在修百度/小红书反爬）。
- 官方免责声明：**仅供学习研究，严禁商用**。商用需自行评估法律风险。
- 它是「跑一次出一份报告」，**不是可订阅的信息源**；要持续监控仍需配合定时任务。
- 需要本地 Chromium/Playwright 环境，老机器上有兼容坑。

### 4. AIHOT — [aihot.news](https://aihot.news)（上游 Skill 在 [khazix-skills](https://github.com/KKKKhazix/khazix-skills)）

**是什么**：中文 AI 资讯的策展 + 热点榜 + 日报，提供**官方 Agent Skill** 与稳定 `/api/v1/*`。

**优势（最符合你的偏好）**
- **完全匿名、只读、无需 API Key、无需 MCP、无账号** —— 真正的「装上就能用」。
- 有稳定版本契约，后端迭代不需要你更新 Skill。
- 有精选池 + 全量池双层，关键词在精选池查空时可用 `mode=all` 兜底（冷门公司常只在全量池）。
- 有 hot-topics（当前在爆什么）、items（关键词/分类）、dailies（日报）。

**局限 / 风险**
- **只覆盖 AI 领域**，不是通用舆情源。
- **用途许可有硬边界**：个人非商业、公益非商业、组织内部免费；**对外商业交付、收费服务、代理接口、数据转售、公开镜像、批量再分发须先取得书面授权**。MIT 只覆盖 Skill 文件，不覆盖数据。
- v1 没有「按 ID 取正文」端点，深度阅读只能靠返回的 summary + 原链。
- 无周报/月报 API（只有网页）。

## 四、涵盖维度矩阵（判断覆盖缺口用）

|---|---|---|
| 热榜/趋势 | ✅ NewsNow 20+ 源、TrendRadar、DailyHotApi | — |
| AI 行业资讯 | ✅ AIHOT | — |
| 中文新闻/时政 | ✅ 澎湃/凤凰/头条/百度热榜 | — |
| 财经行情 | ✅ 财联社/华尔街见闻/雪球 | — |
| 科技/开发者 | ✅ GitHub Trending、HN、V2EX、掘金、IT之家、少数派 | — |
| 国际/地缘 | ✅ worldmonitor | — |
| 网页正文 | ✅ Jina Reader | — |
| 全网搜索 | ✅ SearXNG（自建） | — |
| RSS 订阅 | ✅ RSSHub | — |
| 公众号 | ⚠️ RSSHub 部分路由 | ❌ 需微信读书授权（会过期） |
| 小红书 | ❌ | ❌ Cookie/浏览器会话，封号风险高 |
| 抖音 | ⚠️ 仅热榜标题 | ❌ 作品/评论需抓取 |
| 微博/知乎/B站 | ✅ 热榜/搜索（B站可搜） | ❌ 详情评论需登录 |

**缺口结论**：真正「免授权拿不到」的只有三块 —— **小红书笔记与评论、抖音作品与评论、公众号历史文章**。这三块必然要付出授权成本，建议单独立项而不是塞进单入口硬扛。

## 五、单入口集成方案（已交付）

交付物：`info-hub` Skill（`outputs/info-hub/`），结构：

```
info-hub/
  SKILL.md                  # 分层路由 + 输出规范 + 合规红线
  references/sources.md     # 全源清单：星标/许可/授权成本/风险/命令
  references/hotlist.md     # 热榜维度：源 ID 表 + 自建趋势库 + 故障排查
  scripts/hotlist.mjs       # L0 单入口脚本（零依赖，Node 18+）
```

### 设计要点

1. **按授权成本分层，而不是按平台罗列**：L0 免授权 → L1 配一次长期有效 → L2 需登录态。默认只走 L0/L1。
2. **热榜/趋势维度已内置并实测**：`scripts/hotlist.mjs` 一次拉 20 个源的实时热榜（微博/知乎/抖音/头条/百度/澎湃/贴吧/虎扑/掘金/IT之家/少数派/GitHub/HN/V2EX/虫部落/财联社/华尔街见闻/雪球/凤凰/靠谱）+ AIHOT AI 热点，**全部免 Key 免登录**，实测 21/21 成功。
3. **趋势 ≠ 热榜**：脚本支持 `--json`，配合计划任务留存即可算「连续在榜 / 新上榜 / 掉榜」；要告警推送再上 TrendRadar。
4. **不重造 L2**：小红书/抖音/公众号明确指向成熟工具，并要求先向用户说明授权与封号风险。

### 实测结果（2026-09-21）

```
node scripts/hotlist.mjs --preset all --limit 2 --aihot --json
OK  weibo / zhihu / douyin / toutiao / baidu / thepaper / tieba / hupu
OK  juejin / ithome / sspai / github-trending-today / hackernews / v2ex-share / chongbuluo
OK  cls-hot / wallstreetcn-hot / xueqiu-hotstock
OK  ifeng / kaopu / aihot          → 21/21
```

### 使用

```bash
node scripts/hotlist.mjs --preset cn --aihot      # 中文热榜 + AI 热点
node scripts/hotlist.mjs --preset all --json      # 交给上层做趋势计算
```

### 注意事项（踩过的坑）

- NewsNow 公开 JSON **必须带浏览器形态 UA**，`curl/8.0` 或 `node` 原生 UA 会被 403；脚本已固定为自标识的 `Mozilla/5.0 (compatible; info-hub/1.0; ...)`。
- 返回 `status: cache` 属正常（服务端缓存），脚本会标注「缓存」，不是失败。
- 公共实例勿高频轮询（同端点 ≥ 60 秒）；要高频请自建 NewsNow。

## 六、建议的推进顺序

1. **今天可用**：`info-hub` 装上，热榜/趋势 + AIHOT 立刻可用（零授权）。
2. **本周补纵深**：加 Jina Reader 读全文 + RSSHub 订阅固化（仍零授权）。
3. **确认需要历史趋势**：给 `hotlist.mjs --json` 挂一个每日两次的计划任务。
4. **只有确有必要才上 L2**：先选 1 个平台（建议小红书）单点打通，用插件版 + 本地浏览器，别用服务端批量抓取。
