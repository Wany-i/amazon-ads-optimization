# 亚马逊投放速成（面向业务自动化）

> 目标：**能独立设计并上线一套不出事的广告自动化**。不是成为手工优化师。
> 预计投入：**4~6 小时**（读 + 对着我们已有的代码跑一遍）

---

## 零、为什么自动化的知识面跟手工投放不一样

| | 手工优化师 | **做自动化的你** |
|---|---|---|
| 靠什么 | 手感、类目直觉、经验 | **边界、口径、幂等性** |
| 最怕 | 判断错，慢慢改回来 | **判断错，一次批量放大 100 倍** |
| 必须会的 | 什么时候动手 | **什么时候绝对不能动手** |
| 可以不会的 | —— | 调价手感、类目直觉、后台操作细节 |

**所以本速成的内容配比是**：算法与口径 40% + 边界与安全 40% + 数据结构 20%。
**没有**创意优化、SB/SD 投放技巧、后台点选操作 —— 那些和自动化无关。

## 模块 1：算得对（约 1.5 小时）

**自动化最贵的错误是"用错口径批量放大"。** 公式记错，脚本会忠实地把错误执行一千遍。

### 1.1 三个必须背下来的公式

```
盈亏平衡 ACoS = 单位广告前贡献 ÷ 售价
可接受 CPC    = 售价 × 转化率 × 目标 ACoS
动态点击阈值  = 1 ÷ 转化率
```

**盈亏平衡的逐项扣除**（少扣一项就会系统性高估可承受 ACoS）：

```
售价
 − 产品成本
 − FBA 配送费
 − 平台佣金（售价 × 佣金率）
 − 头程分摊
 − 仓储/其他分摊
 − 退货损耗（售价 × 退货率 × 损失率）   ← 最常被漏掉的一项
= 单位广告前贡献
```

> 服装类目退货率 10%~30%，**不扣退货会高估 15% 以上的可承受 ACoS**。

**实操**：
```bash
node scripts/ads_opt.mjs calc --price 39.99 --cost 8 --fba 7.5 --first-leg 3 \
  --commission-rate 15 --return-rate 5 --target-margin 15 --cvr 8
```
换 5 组参数跑一遍，看结果怎么变。**这是唯一能"算对"的部分，必须练到闭眼能算。**

### 1.2 目标 ACoS：不要拍，要推

| 策略 | 乘数 | 含义 |
|---|---|---|
| launch | **1.40 × 盈亏平衡** | 推新品买排名，利润后置 |
| grow | 1.10 × | 要自己养活自己 |
| dominate | 1.15 × | 抢类目份额 |
| maintain | ≤ 1.0 × | 维持 |

**两条衍生规则**：
- **「砍」跑上限、「加」跑裸盈亏线** —— 允许亏到上限，但只对**真正赚钱**的对象加码
- **目标是产品级的，不是账户级的** —— 同一句"目标 30%"对 55% 毛利是胜利，对 20% 毛利是灾难

### 1.3 ⚠️ 口径陷阱（自动化专属）

手工看报表时，口径错了你能看出来；自动化里口径错了，没人看得出来。

| 陷阱 | 后果 | 对策 |
|---|---|---|
| **归因窗口** | 7 天和 14 天的"销售额"不是一回事 | 全流程固定一个窗口，写进配置 |
| **时区** | 美国站按 PST 切日，你按北京时间切 → 日报永远对不上 | 按站点时区聚合 |
| **币种** | 多站点混算必错 | 按站点分币种，换算率写进配置 |
| **退货率** | 见上，最常漏 | 进公式，按类目取值 |
| **日期文本比较** | 把日期当字符串比大小 | 日期先转成日期类型再比 |
| **重复计数** | 同一词出现在 Auto + Broad 两条记录里 | 按需聚合，别直接 sum |

## 模块 2：分得清（约 1 小时）

**这是自动化的核心设计问题：哪些判断可以自动执行，哪些必须停下来找人。**

### 2.1 判断的确定性分级

| 类型 | 例子 | 能否自动 |
|---|---|---|
| **纯算术** | 盈亏平衡 ACoS、CPC 换算、阈值比较 | ✅ 完全可自动 |
| **确定性规则** | "点击 > 1÷CVR 且 0 单 → 加否定" | ✅ 可自动（但要先验证阈值） |
| **语义判断** | "这个词跟我的产品相关吗" | ⚠️ 只能用模型，且必须门控 |
| **商业判断** | "该不该为了排名接受亏损" | ❌ 必须人工 |

### 2.2 结论：规则层做决策，模型层只做影子

我们那个 `jev-ads-analysis` 项目的核心设计就是这个：

```
规则层（可追溯）  → 主路径，出动作 + 依据
模型层（黑盒概率）→ 影子层，出第二意见
两者不一致        → 转为人工复核
```

**为什么不让模型做主路径**：
- 客户/老板问"为什么这个词要降价"，模型只能答"它给了 0.73" —— **无法复盘**
- 模型的 confidence 在不同输入规模下能漂 ±0.33，**没有标定就不能做门控**

**如果非要用模型**，三条硬约束：
1. **算术全部在代码里算完再传** —— 决策模型不是计算器，且不可靠计数
2. **只给它判断需要的字段** —— 无关内容会扭曲置信度（实测 ±0.33）
3. **必须先做影子标定** —— 用 20~50 个真实样本扫阈值，看准确率/覆盖率曲线

### 2.3 一个判断经验（很值钱）

> **当影子层与规则层大面积不一致时，先怀疑影子层，而不是庆祝发现了分歧。**

我们踩过：第一版 Jev 对 12 个词里的 10 个都判"暂停"，分歧率 91.7%，连 ACoS 26% 的健康词也是。
**根因是我没在指令里写清判断口径** —— 模型不知道什么时候该选哪个动作，退化成最保守的选项。

**判据**：如果模型输出**比规则层更极端、更单一**，几乎一定是设计问题。

## 模块 3：踩得住刹车（约 1.5 小时）

**这部分手工优化师可以靠"小心"混过去，自动化不行 —— 必须写成代码约束。**

### 3.1 动作风险分级（必须硬编码）

| 级别 | 动作 | 自动化策略 |
|---|---|---|
| **只读** | 查数、诊断、生成方案 | 无需确认，随便跑 |
| **低风险写** | 加否定词、暂停明确亏损词 | 可自动，但留痕 |
| **中风险写** | 改出价（±30% 内）、广告位加价一档 | **需确认或严格门控** |
| **高风险写** | 建/删活动、改匹配方式、批量改 >20%、关整个活动 | **必须人工确认 + 影响预估 + 回滚方案** |

**不可逆动作清单**（这些永远不要无条件自动执行）：
`删除活动` / `删除广告组` / `删除关键词` / `改匹配方式` / `批量否定` / `归零出价`

### 3.2 六条必须写进代码的约束

```python
# 1. 批量限速：单次变更 ≤ 对象总量的 20%
assert len(changes) <= max(1, int(len(all_objects) * 0.2))

# 2. 学习期静默：新建或大改后 < 3 天不动（保守取 7 天）
assert days_since_launch >= 3

# 3. 库存闸门：可售天数 < 30 天，禁止一切加投
if days_of_cover < 30: forbid(actions=["加价", "加预算", "扩词"])

# 4. 变更留痕：没有改前值就不准执行
assert change.before_value is not None

# 5. 幂等：同一对象同一周期只允许一次同类变更
assert not has_recent_change(obj, kind, within_days=3)

# 6. 大促静默：大促当天不做结构性调整
if in_peak_event(): forbid(actions=["改结构", "改匹配方式"])
```

> **第 4 条最重要**：`before_value is None` 就意味着**无法回滚**。
> 拿不到改前值的批量工具，不要用。

### 3.3 回滚设计

每条变更记录：

```
时间 / 对象ID / 字段 / 改前值 / 改后值 / 依据 / 预期影响 / 回滚触发条件
```

**回滚触发条件要写具体**，不能写"效果不好就回滚"：

- 3 天后 ACoS 未改善且订单量下降 > 20% → 回滚出价
- 提预算后 3 天转化率未变 → 回滚预算
- 否定后曝光下降 > 40% → 检查是否误否

### 3.4 静默期清单（哪些时候什么都别做）

| 情况 | 为什么 |
|---|---|
| 学习期内（<3 天，保守 7 天） | 频繁调整会**重置/延长**学习期 |
| 大促当天 | 数据不可与日常比 |
| 库存 < 30 天销量 | 加剧断货，比少卖更伤排名 |
| 数据不足（点击 < 1÷CVR） | 样本不够，动了也是噪声 |
| 目标不明确 | 同一个 ACoS，目标不同结论完全相反 |

## 模块 4：接得上数据（约 1 小时）

### 4.1 需要接的三张报表

| 报表 | 回答什么 | 自动化用途 |
|---|---|---|
| **搜索词报告** | 钱花在哪些真实搜索词上 | 收割 / 否定 / 降价（最高频） |
| **广告位报告** | TOS / ROS / PP 各位置效率 | 广告位加价 |
| **SQP 份额报告**（需品牌备案） | 我在这个词上占多少份额、短板在漏斗哪一环 | **判断该不该调广告** |

**SQP 的断崖定位法**（自动化可以直接实现）：

| 断崖位置 | 病因 | **不要做什么** |
|---|---|---|
| 点击份额 < 曝光份额 | 主图/价格/评分 | ❌ 不要加价 |
| 加购份额 < 点击份额 | 详情页/卖点 | ❌ 不要扩量 |
| 购买份额 < 加购份额 | 价格/运费/优惠券 | ❌ 不要怪广告 |

> **份额落差在哪一环，钱就不该花在广告上，而该花在那一环。**

### 4.2 列名与格式陷阱（我们全踩过）

| 陷阱 | 现象 | 对策 |
|---|---|---|
| 列名不统一 | 各工具导出表头不同 | 建别名映射表（大小写/中英/下划线） |
| 比例两种量纲 | `0.125` 和 `12.5` 混用 | **按列判断量纲**（整列最大值 > 1.5 视为百分数） |
| 空/`-` 值 | 自动广告的匹配方式是 `-` | 归一化，**非法值跳过该字段而不是整批失败** |
| 编码 | GBK/UTF-8 混用，中文乱码 | 显式指定 UTF-8 |
| 一个坏值毁一批 | 45 条里 42 条 `Match Type = -` | **逐字段校验 + 跳过，不整批回滚** |

### 4.3 诊断顺序（不要跳，上层会掩盖下层）

```
第 0 层  份额漏斗（SQP）  ← 先判断"该不该调广告"
第 1~2 层  账户 / 广告活动
第 3~4 层  广告组 / 搜索词
第 5 层  广告位
第 6 层  时段
```

**第 0 层的意义**：防止把「转化问题」当「出价问题」而不断加价 —— 独立来源原话：
> 「**竞价只能影响广告竞争与点击成本**。流量不相关、售价变化、库存紧张或页面无法承接时，单独调价通常无法解决转化问题。」

## 验收：能写出这份自动化规格说明就算够用

```
【输入】
- 数据源：搜索词报告（CSV / API），字段映射表
- 频率：每日 / 每周
- 口径：归因窗口 X 天，站点时区，币种

【判断】
- 盈亏平衡 ACoS 的扣项清单与取值来源
- 目标 ACoS 的乘数选择依据
- 动作规则表（每条含阈值 + 依据 + 优先级）

【执行】
- 动作分级：哪些自动、哪些需确认、哪些禁止
- 限速：单批 ≤ 20%
- 幂等：同对象同周期只改一次
- 留痕：改前值必存

【刹车】
- 静默期清单
- 回滚触发条件（具体到数字）
- 降级路径：数据不足 / 权限不足 / 模型不可用时怎么办

【可观测】
- 每次运行产出：动作数、跳过数、需人工数
- 异常告警：口径变化、字段缺失、批量失败
```

**如果这五块都能写清楚，你就够用了。**

## 不用学的清单（省下你的时间）

| 不用学 | 为什么 |
|---|---|
| 手动调价的手感 | 自动化不需要手感，需要阈值 |
| 类目直觉 | 靠时间积累，且自动化不依赖 |
| 广告后台的点选操作 | 自动化只走 API / 报表 |
| 创意优化、主图设计 | 属于 Listing 侧，不是投放自动化 |
| SB / SD 的投放细节 | 除非你的自动化要覆盖它们 |
| 「黄金时段」等玄学 | 无法证伪；分时的正确做法是**降预算降出价，不是暂停** |

## 一句话总结

**自动化够用 = 算得对 + 分得清 + 踩得住刹车 + 接得上数据。**

其中「踩得住刹车」是手工优化师不会强调、但**你必须有**的部分 —— 因为你的错误会被脚本放大。
