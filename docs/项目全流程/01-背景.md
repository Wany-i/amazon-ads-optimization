# 01 · 背景

> 面向接手这个项目的新人：先理解“为什么会有这个项目”，再去看规则、脚本和执行边界。
> 本文所有关键论断都标注来源；无法从素材直接得出的内容标为【推断】。

## 0. 结论先行

| 结论 | 本项目对应的做法 | 主要来源 |
|---|---|---|
| 亚马逊广告不是“没有资料”，而是资料分散、口径不一、难以直接落到动作 | 把官方口径、开源实现、中文实践统一收敛成可执行 SOP | `official-resources.md`、`market-scan.md`、`verification.md` |
| 真正稀缺的不是策略名词，而是“改什么、改成多少、依据是什么” | 每条动作必须写全：对象、现值、目标值、依据 | `README.md`、`SKILL.md` |
| 网上的阈值不能直接照搬 | 非官方阈值逐条取证；达不到证据门槛就降级为“经验起点” | `verification.md` |
| 官方给口径和方向，但通常不给具体运营阈值 | 由本项目补规则表、算术和证据分级 | `official-resources.md` |
| 本项目首先是一套决策层能力，不是自动调价机器人 | 默认只读、只出方案；写操作逐条确认 | `README.md`、`SKILL.md`、`actions.md` |
| 中国卖家的成本口径与官方通用口径不同 | 盈亏平衡 ACoS 额外计入头程、退货损耗等 | `README.md`、`metrics.md` |
| AI 决策模型不能直接替代规则层 | Jev 只做影子层和分歧检测，默认关闭 | `jev-ads-analysis/README.md`、`docs/01-定位与边界.md` |

## 2. 项目为什么存在

### 2.1 问题不是资料太少，而是资料无法直接变成决策

| 现实问题 | 具体表现 | 为什么不能直接使用 | 来源 |
|---|---|---|---|
| ACoS 被当成唯一目标 | 看到 ACoS 高就降价，看到 ACoS 低就加价 | 官方明确说目标 ACoS 因品牌和阶段而异，并专门提醒不要过度关注 ACoS | `official-resources.md` |
| 同一个词在不同教程里给不同阈值 | 零单否定门槛出现 8、10、15、30 等口径 | 没有样本量、观察期和证据强度时，数字不可迁移 | `verification.md` V2 |
| 出价建议脱离利润 | 只讲“建议出价”和“竞价技巧” | 没有盈亏平衡 ACoS，就无法判断某次点击是否值得 | `metrics.md`、`README.md` |
| 把 Listing 问题当成广告问题 | 转化差时不断加价或扩量 | 官方和中文实践都指出，竞价只能影响竞争与点击成本，不能解决页面承接问题 | `official-resources.md`、`verification.md` V23/V29 |
| 调整节奏靠感觉 | 一天没出单就改竞价、改结构 | 频繁调整会重置或延长学习期，数据噪声也会增加 | `verification.md` V6/V20 |
| 批量操作缺乏回滚 | 工具直接改大量关键词或预算 | 没有改前值就无法回滚，批量误操作可能直接破坏账户结构 | `actions.md` |
| 数据渠道不稳定 | 公众号、小红书、抖音、Reddit、垂媒的可达性差异很大 | 不能把“读不到”误写成“没有观点”，也不能把摘要当全文 | `sources-map.md`、`verification.md` 第三/四/六轮 |
| 第三方方案功能重叠 | 数据层、报表层、策略层、自动化层混在一起 | 直接安装多个入口会导致路由摇摆、凭据重复和权限扩大 | `market-scan.md` |

### 2.2 作者在真实工作中要解决的矛盾

| 已知事实 | 来源 | 对项目的含义【推断】 |
|---|---|---|
| 项目以中文写作，强调中国卖家成本口径 | `README.md`、`market-scan.md` | 目标用户不是纯英文代理商，而是中文一线运营和代运营团队 |
| 本机已有 `ziniao-amazon-ads-system` 作为 Ads API 数据层 | `market-scan.md`、`data-integration.md` | 作者缺的不是“再多一个取数工具”，而是取数之后的诊断与决策 |
| 本机已有多种渠道可达性实测 | `sources-map.md`、`verification.md` | 作者接受“信息不完整”是长期约束，而不是临时障碍 |
| 项目要求无 API Key 也能用于 Markdown 和本地脚本 | `README.md` | 降低试用门槛，同时把真正的写操作留在人工确认之后 |
| Jev 项目先在 45 个真实搜索词上标定 | `jev-ads-analysis/README.md` | 作者愿意试验 AI，但不愿让未标定模型直接碰广告决策 |
| 规则验证过程中推翻了自己 3 处写法 | `README.md`、`verification.md` | 项目把“被证据纠正”当成正常流程，而不是失败 |
| 市场扫描发现本机没有亚马逊广告/PPC 技能 | `market-scan.md` | 自建决策层是补齐生态缺口，不是重复已有能力 |

### 2.3 如果沿用“经验贴拼装”的方式，会出现什么后果

| 失败模式 | 产生原因 | 项目中的防线 | 来源 |
|---|---|---|---|
| 把经验阈值当行业标准 | 不知道来源、样本和适用类目 | 证据分级；达不到门槛就标“经验起点/单一来源” | `verification.md` |
| 出价方向正确但数值错误 | 没有把目标 ACoS 翻译成 CPC | 可接受 CPC = 售价 × CVR × 目标 ACoS | `metrics.md`、V1 |
| 短期无单就否定有效词 | 小样本被过度解释 | 动态点击阈值、1÷CVR、至少看 7 天、必要时看 14 天 | `verification.md` V24/V28/V30 |
| 用暂停解决分时问题 | 以为暂停只省花费，忽略连续性 | 改为降预算与出价，不暂停 | `README.md`、`verification.md` 第六轮 |
| 广告结构越调越碎 | 没有迁移和原位置否定闭环 | 收割后建 Exact，并在原位置否定精确 | `actions.md` |
| 把 AI 置信度当决策依据 | 置信度会随上下文漂移 | Jev 只检测分歧，不替代规则层 | `jev-ads-analysis/docs/01-定位与边界.md` |
| 取数合规风险 | 抓后台页面、共享密钥、跨账号混用 | 只走官方 API 或后台导出，不回显密钥和内部 ID | `data-integration.md`、`SKILL.md` |

## 3. 为什么不能直接照搬网上内容

| 内容来源 | 已经有什么 | 为什么不能直接照搬 | 本项目怎么处理 | 来源 |
|---|---|---|---|---|
| Amazon 官方 Academy / Library / API | 课程、认证、指南、字段口径 | 给方向和口径，通常不给具体运营阈值；中国卖家成本项也不完整 | 作为最高权威来源；只借口径，不把“最佳实践”当阈值 | `official-resources.md` |
| 海外开源 Skill / 指南 | 出价公式、否定词、收割、广告位、预算倍数等实现 | 阈值分歧；有的只覆盖数据层；有的实现含脆弱抓取；镜像会制造“伪多源” | 交叉验证；只 vendor 经审查的纯文本方法论 | `verification.md`、`market-scan.md` |
| 中文公众号 / 垂媒 | SOP、口诀、场景化经验、大促和断货打法 | 多为摘要级、来源不统一、部分文章被反爬；口诀不是阈值 | 只作为检索线索和佐证；与官方冲突时以官方为准 | `sources-map.md`、`verification.md` |
| 第三方广告数据服务 | 报表、授权、部分管理动作 | 解决的是“拿到数据”，不解决“数据说明该做什么”；还会增加凭据维护 | 优先复用本机已有数据层，不重复接入 | `market-scan.md`、`data-integration.md` |
| AI 决策模型 | 可做语义分类和第二意见 | 不可解释、会记错数、置信度不稳定、官方没有背书竞价动作 | 只做影子层；先标定，后人工复核 | `jev-ads-analysis/README.md` |
| 现成“自动调价机器人” | 可能能批量执行 | 默认动作不可逆，缺少样本闸门、库存闸门和回滚条件 | 默认只出方案，写操作逐条确认 | `README.md`、`actions.md` |

【推断】作者的核心判断是：信息不缺，缺的是一个可信的“收敛层”。这个收敛层必须同时做四件事：确认官方口径、标注证据强度、翻译成动作、限制执行风险。

## 4. 项目做出的关键取舍

| # | 取舍 | 选择 | 放弃了什么 | 依据 |
|---|---|---|---|---|
| 1 | 定位在决策层还是数据层 | 只做诊断、决策、复盘；取数交给已有数据层 | 不自己维护一整套 Ads API 授权与代理 | `README.md`、`data-integration.md` |
| 2 | 以官方还是以经验贴为权威 | 官方指南/API 优先 | 放弃“某个公众号说得更实操所以照抄” | `SKILL.md`、`sources-map.md` |
| 3 | 以 ACoS 还是以利润为锚 | 先算盈亏平衡 ACoS，再定目标 ACoS | 放弃一个通用的“最优 ACoS” | `README.md`、`official-resources.md` |
| 4 | 阈值是固定还是动态 | 优先用本品 CVR 推导，固定值只作起点 | 放弃跨类目通用数字 | `verification.md` V28 |
| 5 | 是否追求“证据看起来多” | 镜像不算独立源，摘要和单篇单独标注 | 放弃用数量堆出虚假确定性 | `verification.md` |
| 6 | 中国卖家成本是否单列 | 计入头程分摊、退货损耗等 | 放弃直接使用通用毛利口径 | `metrics.md`、`official-resources.md` |
| 7 | 默认是否执行写操作 | 默认只读，只出方案 | 放弃“一键自动优化”的卖点 | `README.md`、`actions.md` |
| 8 | 批量变更如何限速 | 单次不超过对象总量 20%；记录改前值 | 放弃一次性全量调整的效率 | `actions.md`、`verification.md` V7 |
| 9 | 是否抓取后台页面 | 明确禁止；只走官方 API 与后台导出 | 放弃更省事的页面抓取路径 | `data-integration.md` |
| 10 | 第三方方案是安装还是 vendor | 只 vendor 经审查的 Markdown 方法论，不注册独立入口 | 放弃“装得越多能力越全”的直觉 | `market-scan.md` |
| 11 | Jev 是主路径还是影子层 | 规则层主路径，Jev 只给第二意见 | 放弃让模型直接决定加价/降价/暂停 | `jev-ads-analysis/docs/01-定位与边界.md` |
| 12 | 渠道读不到怎么办 | 明确写“不可达”，不用推断填空 | 放弃把海外社区共识假装成已覆盖 | `verification.md` 局限声明 |
| 13 | 是否做成多入口技能 | 只保留一个入口，避免 Agent 路由摇摆 | 放弃按功能拆成多个独立 Skill | `market-scan.md` |
| 14 | 证据不足时怎么办 | 标为“经验起点/单一来源”，进入待补 | 放弃把推测包装成规则 | `verification.md` |

### 5.2 三处被推翻的写法

| 原写法 | 为什么错 | 改后 | 来源 |
|---|---|---|---|
| Product Pages ACoS 低就提高 PP 加价 | 独立实现明确否定“Product Pages boost” | 按 ACoS 相对盈亏平衡线的倍数判断，PP 只有收紧档 | `README.md`、`verification.md` V11 |
| 收割 = 订单 ≥2 且 ACoS ≤ 目标 | 稳定转化但 ACoS 差的词，更需要独立活动来调出价 | 改为转化速率制；ACoS 只用于定价 | `README.md`、`verification.md` V17 |
| 时段低迷就暂停投放 | 暂停会破坏连续性、降低权重与质量得分 | 降预算与出价，不暂停 | `README.md`、`verification.md` 第六轮 |

### 5.3 Jev 实验带来的背景结论

| 事实 | 对本项目的意义 | 来源 |
|---|---|---|
| Jev 默认关闭，配置缺失时只输出“未接入/待标定” | 没有标定就不把模型结论当决策 | `jev-ads-analysis/README.md` |
| 45 个真实搜索词做过首次阈值标定 | 项目接受“模型可用，但需要按实际 state 形状校准” | `jev-ads-analysis/README.md` |
| 一致组均值 0.820，分歧组均值 0.555 | 置信度具有区分度，但仍不能替代可解释规则 | `jev-ads-analysis/README.md` |
| 41 倍 state 膨胀下选中答案 10/10 不变，置信度漂移 ±0.33 | 只用分歧检测，不用置信度绝对值 | `jev-ads-analysis/README.md` |
| 官方 use-case-map 的广告场景不含加价/降价/暂停/否词 | 本项目做的是官方未列自定义场景，必须自己验 | `jev-ads-analysis/docs/01-定位与边界.md`；官方页面 `docs.typesafe.ai/concepts/use-case-map`（2026-09 抓取，**未保存快照**） |

【推断】这也是项目选择“规则层主路径 + AI 影子层”的根因：广告优化首先要回答“为什么这么调”，而不是“模型觉得概率多高”。

## 6. 新人接手时应该先建立哪些判断

| 遇到什么 | 先问什么 | 去哪里看 |
|---|---|---|
| 看到一个阈值 | 有没有 ≥5 条佐证？是不是单一来源？适用什么类目和样本？ | `verification.md` |
| 看到一个出价数字 | 盈亏平衡 ACoS、目标 ACoS、CVR 是否已知？ | `metrics.md`、`SKILL.md` |
| 看到一个动作 | 对象、现值、目标值、依据、回滚条件是否齐全？ | `SKILL.md`、`actions.md` |
| 看到“应该加预算” | 库存是否足够？预算是否烧穿？ACoS 是否达标？ | `actions.md` |
| 看到“暂停” | 是否只能用暂停解决？有没有降预算/降出价替代？ | `verification.md` 第六轮 |
| 看到跨平台结论 | 币种、站点、时间窗是否统一？ | `SKILL.md` 输出纪律 |
| 看到 AI 建议 | 是否只是影子层？有没有经过人工复核？ | `jev-ads-analysis/docs/01-定位与边界.md` |
| 看到一个渠道“没有资料” | 是不可达、未检索，还是确实没有？ | `sources-map.md`、`verification.md` |
