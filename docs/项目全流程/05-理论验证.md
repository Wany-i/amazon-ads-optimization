# 05 · 理论验证

> **结论先行**：这套方法论在 2026-09-21 做了六轮交叉验证：来源编号覆盖 S1–S11、C1–C32、O1–O2；累计整理出 V1–V32 共 32 条非官方理论/阈值条目，记录 30 处修正，其中 3 处直接推翻了自己的原有写法。
>
> 但这不是亚马逊内部实验，也不是控制变量 A/B 测试。它证明的是：**公式与方向有没有多个独立出处、阈值是否被单一来源支配、哪些结论只能当经验起点。** 可信度必须按证据等级使用。

## 一、验证原则与阅读方法

### 1.1 验证规则

| 规则 | 做法 |
|---|---|
| 权威优先级 | Amazon 官方指南 / API 文档 > 官方 Academy > 海外主流来源 > 国内公众号 |
| 非官方条目门槛 | 至少 5 条佐证或直接证据；不足则降级 |
| 独立性 | 同一实现的分发镜像不重复计数；S7 是 S5 的镜像 |
| 来源结构 | 开源 Skill、技能市场 Skill、中文实践、官方口径 |
| 冲突处理 | 保留分歧；能论证机制强弱时采纳更强的一派，并标注另一派 |
| 输出纪律 | 每条结论写明来源、强度、修正动作与未解决项 |

**事实**：这些规则来自 `verification.md` 的“证据来源编号”“独立性与局限声明”。

### 1.2 三类证据不是同一件事

| 证据形态 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 公式级交叉验证 | 两个以上独立实现得到同一算术关系 | 不一定证明该阈值适合你的类目 |
| 规则级多源互证 | 同一方向被多个来源独立提出 | 具体数字未必有共识 |
| 经验起点 / 单一来源 | 可以作为测试假设 | 不能当行业共识或自动执行依据 |

### 1.3 事实与推断

- **事实**：来源、原文含义、实测渠道结果、公式与差异记录。
- **推断**：当来源冲突时，本项目为什么采纳某一派；为什么某条机制比另一条更合理。
- 本文中的“结论”如果超出原文的直接表述，均明确写为“推断”。

## 三、每轮新增了什么证据源

### 3.1 第一轮：开源实现 + 中文摘要 + 官方口径

**新增来源**：S1–S9 开源 Skill / 技能市场实现；C1–C8 中文公众号摘要；O1–O2 Amazon 官方指南。S7 是 S5 的镜像，不计为独立来源。

**验证结果**：

| 条目 | 结论 | 强度 |
|---|---|---|
| V1 | 可接受 CPC = 目标 ACoS × 售价 × CVR | 多源验证，公式级 |
| V2 | 零单词按点击加否定，但原阈值 15 偏高 | 方向多源；数值改为动态 |
| V3 | 调出价最小点击样本取 20 | 多源验证，取保守值 |
| V4 | 单次降价 -20%~-30% | 多源验证 |
| V5 | 出单词迁移 Exact；补充 80% 起手出价 | 多源验证 |
| V6 | 学习期不频繁调整；具体天数无共识 | 机制多源；7 天为经验默认 |
| V7 | 批量变更限速，单次 ≤20% | 多源验证 |
| V8 | 库存不足不加投 | 概念多源；30 天为经验值 |
| V9 | 不应只优化 ACoS | 多源验证，含官方 |
| V10 | 目标 ACoS 兜底区间：Manual 25–35%、Auto 35–45%、默认 30% | 三源吻合 |

**明确降级的 8 处**：CTR < 0.2%、TOS CVR ≥ 1.5 倍加价、分档降价规则、大促 CTR/CVR 反向数字、匹配方式角色分工、时段集中 40%~50% 预算、词簇法、SQP 断崖法。

### 3.2 第二轮：新增两个独立实现，开始推翻旧写法

**新增来源**：S10 `amazon-operators-field-guide`、S11 `RedHen-Labs`。

**新增结论**：

| 条目 | 结论 | 处理 |
|---|---|---|
| V11 | 广告位按 ACoS 相对 BE 的倍数判断；Product Pages 没有加价档 | **推翻旧的 PP 加价写法** |
| V12 | 目标 ACoS = 盈亏平衡 × 策略乘数 | 与利润公式表达等价 |
| V13 | 日预算 = 预期 CPC × 倍数；最小日预算 $5 | 公式补入方法论 |
| V14 | Exact 100% → Phrase 85% → Broad 80% → Auto 75% | Auto 档位无共识 |
| V15 | 分时从单源升级为双源；补工具挂掉后高 bid 不恢复的风险 | 20%~30% 幅度、傍晚到夜间窗口 |
| V16 | 盈亏平衡 ACoS = 贡献边际百分比 | 与官方 profit margin 口径一致 |
| V17 | 收割判据是转化速率，不是 ACoS | **推翻旧的 ACoS 收割闸门** |

**重要分歧**：S1 一派用“ACoS ≤ 目标”决定是否收割；S10 明确说不要用 ACoS/margin 决定“是否收割”，因为一个稳定转化但 ACoS 差的词，恰恰最需要独立活动来单独调出价。**本项目采纳 S10，并在正文保留另一派做法供对照 —— 这是推断，不是原文一致结论。**

### 3.3 第三轮：中文公开媒体与跨来源数学收敛

**新增来源**：C9–C19，主要来自搜狗微信检索摘要。雨果网当时整站反爬，尚未读到正文。

**新增结论**：

| 条目 | 结论 | 强度 |
|---|---|---|
| V18 | 日预算下限 = 出 1 单所需点击量 × CPC | 中文来源、S10、本项目三种表达数学收敛 |
| V19 | 低基础出价 + TOS 高比例加价 | 中外来源独立复现机制 |
| V20 | 频繁调整会重置/延长学习期 | 多源机制共识，强于具体天数 |
| V21 | 生命周期分档：新品、成长、成熟 | 中外共识 |

## 五、三处被验证推翻的原写法

| # | 原写法 | 新写法 | 推翻原因 | 证据 |
|---|---|---|---|---|
| 1 | Product Pages ACoS 明显更低 → 提高 PP 加价 | 没有“Product Pages boost”；PP 只应收紧 | 把位置 ACoS 误读为独立加价信号；无负修饰符，降基础出价又会削弱所有位置 | S10 直接反驳，V11 多源相邻支持 |
| 2 | 订单 ≥2 且 ACoS ≤ 目标 → 建 Exact | 收割看转化速率：1~2 单/周 → stacked，≥2 单/周 → 独立 Exact | ACoS 是“收割后怎么定价”的问题，不是“是否收割”的问题；稳定转化但 ACoS 差的词尤其需要独立活动调价 | S10 方法论，V17 |
| 3 | 第 6 层：降该时段出价 / 暂停投放 | 降该时段出价与预算；不要暂停 | 暂停破坏广告连续性，可能降低权重与质量得分，恢复位置可能更贵 | C29、C21、S10、O2、C14/C9 |

### 5.1 为什么这三处比普通阈值修正更重要

**事实**：它们不是改一个数字，而是改了动作的**因果假设**。

**推断**：一个错误的方法论假设会被自动化批量放大。例如“PP 低 ACoS 就加价”会把一个位置现象升级为账号级批量加价；“ACoS 差就不收割”会让最需要单独控价的词继续留在失控位置；“暂停做分时”会把省下的时段花费变成系统状态成本。

## 七、诚实局限声明

### 7.1 事实层面的限制

1. **渠道限制**：Reddit、小红书、知乎等渠道未完整纳入；部分原文因反爬、403、登录态或 JS 渲染无法取得。
2. **摘要限制**：中文来源除雨果网正文外，多通过搜狗微信摘要获取，不能保证拿到完整论证。
3. **单源实证**：大促 CTR/CVR 反向变动、新词占比、长尾 CVR 等数字来自 C6 单篇，且原文未获取。
4. **镜像排除**：S7 是 S5 的分发镜像，不计为独立来源。
5. **样本偏向**：开源 Skill 生态以 2025–2026 年新项目为主，方法偏向阈值化、批量表与审批闸门，可能高估这种风格的代表性。
6. **时间敏感**：所有验证完成于 2026-09-21；广告后台、API、政策与市场环境都可能变化。

### 7.2 推断层面的限制

1. **不是控制实验**：验证以公开文档与实现互证为主，没有做同一账号的随机分组 A/B 测试。
2. **不是内部机制证明**：外部来源可以支持“频繁调整影响学习”“暂停影响连续性”等机制解释，但不能证明 Amazon 内部排序与广告权重的具体算法。
3. **采纳存在判断成分**：例如收割判据采纳 S10 而非 S1，是依据因果论证强度做的推断，不是来源全体一致。
4. **精确阈值不等于普适最优**：TOS/ROS/PP 倍数、Auto 75%、最小 $5、30 天库存都只是可测试起点。
5. **未证明长期稳定**：六轮验证只能证明在采编时点的证据关系，不能证明半年后仍然成立。

## 九、最终应该怎么信

### 可以高度信任

**多源验证的算术与稳健方向**：盈亏平衡 ACoS、目标 ACoS、可接受 CPC、日预算下限、`1 ÷ CVR` 动态阈值、20 次点击保守样本、单次 -20%~-30%、批量 ≤20%、库存不足不加投、收割看转化速率、不要暂停做分时。

### 可以作为框架使用

**多源方向 + 单一精确值**：广告位倍数框架、生命周期分档、否词三条件、流量 vs Listing 两层对比、大促后自然权重验证。使用时要保留来源标签，并把精确数值当测试起点。

### 只能当经验起点或待补

CTR 0.2%、TOS 1.5 倍、大促反向数字、2:4:4、30/50/20、Auto 75%、最小 $5、SQP 断崖法、词簇法。**这些内容可以启发验证，但不能被自动化系统当成无条件规则执行。**

> **一句话结论**：六轮验证显著提高了方法论的可追溯性和安全性，但没有把“有出处”变成“对所有账号都最优”。最可靠的用法是：公式按官方与多源口径执行，阈值按自家数据校准，单一来源与经验起点必须保留人工门控。
