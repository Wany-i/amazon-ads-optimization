# 03 · 已有方案调研

> 调研目标：在做自研之前，先回答“官方、海外开源、中文公开媒体分别已经解决了什么，还缺什么，为什么不能直接拿来用”。
> 本文结论先行；事实标注来源，推断明确标注【推断】。
> 对来源能力的归纳和方案比较属于分析判断；未直接引用来源、也未标【事实】的内容按【推断】处理。

## 0. 结论先行

| 结论 | 判断 | 来源 |
|---|---|---|
| Amazon 官方体系完整，适合做权威口径和基础理论 | 【事实】Academy、Library、认证、What's New、API 文档均可访问 | `official-resources.md` |
| 官方不提供大多数一线运营需要的具体阈值 | 【事实】官方给方向和概念，不给“点击 ≥N 才否定”这类运营决策 | `official-resources.md` |
| 海外开源已有成熟方法论轮子，但分散、口径冲突、质量不一 | 【事实】11 个独立实现被纳入验证，且出现 8/10/15/30 等不同阈值 | `verification.md`、`market-scan.md` |
| 中文公开媒体有大量实战 SOP，但可获取性和可核验性有限 | 【事实】搜狗微信可用摘要；小红书、知乎、Reddit 等仍受限 | `sources-map.md`、`verification.md` |
| 本机生态里数据层已有轮子，决策层是缺口 | 【事实】有 `ziniao-amazon-ads-system` 数据层；技能市场没有亚马逊广告/PPC 技能 | `market-scan.md` |
| 因此最后选择自研的是“决策规则 + 证据分级 + 中国卖家口径 + 本机数据闭环” | 【推断】这不是重复造取数轮子，而是补齐决策层 | `market-scan.md` |
| 自研后仍只 vendor 一个方法论，不注册多个重复入口 | 【事实】vendor `nexscope amazon-ppc-campaign`，唯一入口仍是本 Skill | `market-scan.md` |

| 调研层 | `ziniao-cross-border-platform-data-research` | 跨境数据研究 | 不是广告投放优化 | `market-scan.md` |
| 第三方代理 API | Linkfox / Zero2Ai / Nexscope | 数据与管理 | 增加凭据、费用和供应商依赖 | `market-scan.md` |
| 决策规则层 | 无现成完整方案 | 阈值、出价算术、中国口径、证据分级 | 必须自建 | `market-scan.md` |

【事实】市场扫描的结论是：投放优化方法论层已有成熟轮子，本项目的差异化在“决策规则表 + 本机 Ads API 数据层闭环 + 中国卖家口径”。来源：`market-scan.md`。

## 8. 为什么最后决定自己写

| 原因 | 具体证据 | 结果 | 来源 |
|---|---|---|---|
| 官方口径解决“原则”，不解决“数值动作” | 官方不讲点击阈值、PP 倍数等 | 自建规则表和动作库 | `official-resources.md` |
| 开源实现多但分散、冲突、有镜子源 | 阈值 8/10/15/30；S7 是 S5 镜像 | 交叉验证、去重、分级 | `verification.md` |
| 中文实践丰富但无法当权威 | 摘要级、反爬、来源不统一 | 只作佐证与线索 | `sources-map.md` |
| 现有数据层已经存在 | 本机有 `ziniao-amazon-ads-system` | 不重复造数据轮子 | `market-scan.md` |
| 中国卖家成本口径缺位 | 官方和多数开源不含头程/退货细节 | 补 `metrics.md` 口径 | `official-resources.md`、`metrics.md` |
| 写操作风险高 | 批量变更、不可逆、无回滚 | 默认只读 + 限速 + 留痕 | `README.md`、`actions.md` |
| 多入口会破坏 Agent 路由 | 直接安装多个重叠技能会造成路由摇摆 | vendor 一个方法论，保持单入口 | `market-scan.md` |
| AI 决策需要影子层 | 置信度漂移、官方无背书竞价动作 | 规则主路径 + Jev 影子层 | `jev-ads-analysis/README.md` |

【推断】“自己写”的准确含义不是把所有东西重写，而是补充缺少的决策层、证据层和安全层；取数、官方文档、成熟方法论仍尽量复用。
