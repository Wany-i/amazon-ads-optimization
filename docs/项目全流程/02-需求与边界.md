## 1. 需求陈述

【事实】本项目把亚马逊广告优化定义为一条固定主链：

```text
拉数 → 诊断 → 决策 → 执行 → 复盘
```

来源：`README.md`、`SKILL.md`。

【事实】项目要解决的是“决策层”问题：接在官方 Ads API 或后台报表导出之上，输出具体动作，而不是重新实现取数、授权和全量广告管理 API。来源：`README.md`、`data-integration.md`。

【推断】这意味着项目成功与否，不应只用“能不能连上 API”衡量，而应看它能否把已有数据稳定地翻译成有依据、能复核、带止损条件的决策。

【待补】六轮验证的证据主要集中在 SP；SB、SD、DSP 是否拥有同等级别的逐条规则证据，素材没有逐项说明。接手者不得把 SP 阈值自动外推到 SB/SD/DSP。

## 4. 不在范围内（Out of Scope）

| 不做的事 | 原因 | 替代做法 | 来源 |
|---|---|---|---|
| 不做默认自动调价 | 写操作不可逆，风险和上下文确认不足 | 只出方案；用户明确授权后再写 | `README.md`、`actions.md` |
| 不自己实现完整 Ads API 客户端 | 项目定位是决策层，本机已有数据层能力 | 复用 `ziniao-amazon-ads-system` 或后台 CSV | `data-integration.md`、`market-scan.md` |
| 不抓取卖家后台或广告后台页面 | 合规与稳定性不可接受 | 官方 API、本机代理能力、手动导出 | `data-integration.md` |
| 不给通用“最优 ACoS” | 每个品牌目标不同，必须先算盈亏平衡线 | 先算 break-even，再定目标 ACoS | `official-resources.md` |
| 不用行业均值硬凑缺失数据 | 会造成虚假精确 | 明确说缺哪张报表、哪些结论不能给 | `SKILL.md`、`data-integration.md` |
| 不跨店铺/跨账号混用数据 | 权限与归因风险 | 一店一诊断、一店一币种口径 | `SKILL.md` |
| 不默认启用未标定 AI 决策 | 置信度会随 state 漂移，官方未背书竞价动作 | Jev 默认关闭；标定后再做影子层 | `jev-ads-analysis/README.md` |
| 不把摘要当全文 | 渠道原文可能被反爬或未取得 | 标注证据等级与可达性 | `verification.md` |
| 不把镜像源算独立证据 | 数量会伪造共识 | 只计独立实现 | `verification.md` 独立性声明 |
| 不做账户法律、税务、知识产权尽调 | 素材未覆盖 | 交由专业合规角色 | 【待补】 |

## 5. 输入需求

### 5.1 开始前必须问清四件事

| # | 输入 | 为什么必须 | 缺失后果 | 来源 |
|---|---|---|---|---|
| 1 | 站点与币种 | 决定费用项、汇率和跨站可比性 | 无法统一成本与 ACoS 口径 | `SKILL.md` 第 0 步 |

## 7. 硬约束

### 7.1 合规与数据边界

| 约束 | 要求 | 禁止 | 来源 |
|---|---|---|---|
| 取数通道 | 官方 Ads API、本机已有代理能力、后台手动导出 CSV | 抓取卖家后台/广告后台页面 | `data-integration.md` |
| 凭据 | 由数据层技能自行处理 | 本项目接触、回显、复制密钥 | `data-integration.md` |
| 输出脱敏 | 只输出业务可读名称与结论 | 输出内部 profile ID、代理地址、密钥、原始 JSON | `SKILL.md` |
| 账号隔离 | 一店一诊断 | 跨卖家/跨账号混用数据 | `SKILL.md` |
| 第三方技能 | 先做安全审查 | 引入未审查代码；提供后台账号密码 | `market-scan.md` |
| 渠道许可 | 注意商用、转载、批量再分发限制 | 把学习用途来源直接用于商业交付 | `信息源聚合评估_2026-09-21.md` |

### 7.2 不可逆操作与写操作约束

| 风险级别 | 动作 | 执行要求 | 来源 |
|---|---|---|---|
| 只读 | 查询、算指标、诊断、生成报表 | 可直接执行 | `actions.md` |
| 低风险写 | 加否定词、暂停单个明确亏损词 | 说明依据后执行；用户可免确认授权 | `actions.md` |
| 中风险写 | 出价 ±30% 内、广告位加价一档、预算 +≤30% | 必须逐条确认 | `actions.md` |
| 高风险写 | 建/删活动、改匹配方式、批量 >20%、关活动、预算 >30% | 逐条确认 + 影响预估 + 回滚方案 | `actions.md` |
| 默认策略 | 只出方案，不落盘 | 用户明确说“直接改”才进入写流程 | `actions.md` |
| 删除 | 删除不可逆 | 仅在确认无历史价值且明确确认后执行 | `actions.md` |

### 7.3 样本量与观察窗口

| 场景 | 阈值/窗口 | 说明 | 来源 |
|---|---|---|---|
| 关键词出价调整 | 点击 ≥20 | 独立实现明确要求最低统计显著性 | `verification.md` V3 |
| 零单词否定 | 优先用 1÷CVR 动态推导，下限 5 | 不照搬固定 10 次点击 | `verification.md` V28 |

| 判断是否有问题 | 一天十几个点击零单不足以下结论 | 先积累数据 | `verification.md` V30 |
| 常规复盘窗口 | 至少 7 天 | 短周期噪声大 | `verification.md` V30 |
| 异常期复盘窗口 | 14 天 | 大促、断货、改价、优惠券到期、配送变化 | `verification.md` V30 |
| 结构判断 | 14~30 天 | 7 天不足以判断结构 | `metrics.md` |
| 调价后观察 | 3~5 天 | 同一对象两次调价间隔 ≥3 天 | `actions.md`、`verification.md` V26 |
| 单次调价幅度 | −20%~−30% | 降价落在多来源交集内 | `verification.md` V4 |

### 7.4 学习期与节奏约束
