# 04 · 方法论设计

> **结论先行**：这套方法论不是“规则大全”，而是一条决策流水线：先用财务锚判断能不能花钱，再用份额漏斗判断钱该不该花在广告上，随后按账户、活动、结构、搜索词、广告位、时段的顺序定位问题，最后用证据量、学习期、库存、大促状态和执行风险做门控。
>
> 九个层次固定排序的关键原因只有一个：**上层问题会污染下层数据**。如果跳过上层，后面的阈值即使算得再精确，也只是在错误的地基上装修。

---

## 一、设计目标与阅读约定

### 1.1 这套设计要解决什么

它要把广告优化拆成四个可审计的问题：

| 问题 | 对应设计 |
|---|---|
| 这笔钱最多能花多少？ | 盈亏平衡 ACoS、目标 ACoS |
| 这个对象值不值得继续花钱？ | SQP 份额漏斗、可接受 CPC、动态点击阈值 |
| 问题在哪一层？ | 9 层诊断框架 |
| 什么时候不能动、能动多少？ | 门控、动作分级、P0/P1/P2、限速与回滚 |

**事实**：上述结构来自 `SKILL.md` 的“拉数 → 诊断 → 决策 → 执行 → 复盘”流程，以及 `diagnosis.md` 的固定层级顺序。

### 1.2 两条不变式

1. **先算钱，再调广告。** 没有盈亏平衡 ACoS，任何“涨还是降”都没有利润坐标。
2. **先判短板，再调参数。** SQP 或转化短板没有定位前，不能把 Listing/价格问题误当成出价问题。

### 1.3 证据强度标记

| 标记 | 含义 | 使用方式 |
|---|---|---|
| **多源验证** | ≥5 个独立来源支持 | 可以作为结论使用 |
| **单一来源** | 1~2 个来源支持 | 参考，不能当行业共识 |
| **经验起点** | 无外部来源，或只有本项目自建设定 | 必须用自己的数据校准 |
| **待补 / 未验证** | 明确尚未取得证据 | 不能当结论 |

### 1.4 事实与推断的区分

- **事实**：能追到官方文档、开源实现、公开文章或实测记录的内容。
- **推断**：本项目对这些事实之间的因果关系、排序理由、适用边界的判断。
- 下文表格中，带“依据来自……”的是事实；带“为什么这样排”的是推断。

## 二、9 层诊断框架

### 2.1 总表：每层回答什么，为什么放在这里

| 层 | 名称 | 核心问题 | 放在这个位置的理由 | 前置或跳层条件 |
|---|---|---|---|---|
| 0 | 份额漏斗（SQP） | 短板在曝光、点击、加购还是购买？ | 先判断“该不该调广告”，防止把转化问题当出价问题 | 需品牌备案；无备案则跳过并声明 |
| 1 | 店铺 / 账户 | 广告有没有蚕食自然位？TACoS 与利润是否失衡？ | 账户是全局约束；单活动最优不等于店铺最优 | 至少 3 周，推荐 4 周周粒度数据 |
| 2 | 广告活动 | 预算、ACoS、IS、学习期是否异常？ | 活动是预算与学习期的边界，先确认钱是否被正确约束 | 新活动或大改后 < 3 天不调出价与结构 |
| 3 | 广告组 / 关键词结构 | 词包、匹配方式、商品分组是否互相打架？ | 结构错误会污染搜索词层，先拆清归因关系 | 同组混品类、价格带或 ROAS 表现时先拆组 |
| 4 | 搜索词 | 哪些词浪费、哪些词收割、哪些词迁移？ | 搜索词是最高频、最直接可执行的证据层 | 点击样本不足时不能下否定/收割结论 |
| 5 | 广告位 | 不同位置的边际效率是否值得加价？ | 是在词与转化质量基本稳定后做的“分配修正” | 先有订单和销售额，不能只看曝光或点击 |
| 6 | 时段 | 某时段是否显著更好或更差？ | 时段是最后一层调节器，依赖稳定基线与足够数据 | 全天平稳就不做；不要用暂停实现分时 |
| 7 | 大促 / 旺季 | 指标变化是异常还是大促期反向表现？ | 大促数据不可与日常直接比较，需要覆盖日常结论 | 大促期间不做结构性下调 |
| 8 | 新增需求 | 新词、长尾词、需求扩张在哪里？ | 止血与结构稳定后再找增量，避免新增流量继续漏损 | 先完成否词、收割与结构收敛 |

**这 9 层的性质**：层名、顺序和阈值来自 `diagnosis.md`；其中第 7、8 层是后期补充的专项层。**“为什么用这个顺序”是推断，不是亚马逊官方规定的诊断顺序。**

### 2.2 为什么顺序固定

**推断一：上层是下层结果的定义域。** 如果 Listing 承接差，搜索词层的“高点击 0 单”既可能是词不相关，也可能是详情页问题；先在第 0 层判断短板，才能给第 4 层正确含义。

**推断二：账户与活动决定约束，结构决定归因。** 预算没有烧穿、学习期没结束、同组词在互相竞争时，搜索词数据不能直接代表某个词的真实效率。

**推断三：搜索词层是最频繁的出手点，但不是第一诊断点。** 它见效快、数据细，因此放在结构之后；如果先调搜索词，容易把结构造成的假象当成词的问题。

**推断四：广告位与时段是调节器，不是根因层。** 它们改变同一批流量的分配与价格，无法修复错误关键词、错误 Listing 或错误库存状态。

**推断五：大促与新增需求是覆盖层。** 第 7 层防止用不可比数据做日常决策；第 8 层在基础流量干净后寻找增量。

### 2.3 什么时候必须停下

| 条件 | 处理 | 依据强度 |
|---|---|---|
| 无品牌备案，拿不到 SQP | 明确声明缺第 0 层，只能用广告报表做粗诊断 | 事实：SQP 需要 Brand Registry |
| 点击 < 10，或未达到本品 `1 ÷ CVR` 推导线 | 不据此否词、不据此暂停 | 多源验证：低样本不下结论 |
| 新活动或大改后 < 3 天 | 不调出价、不改结构；保守默认 7 天 | 机制多源验证；具体天数经验起点 |
| 大促高峰或大促当天 | 不做结构性下调；先按第 7 层反向解读 | 事实：大促数据不可比 |
| 库存 < 30 天销量 | 停止所有加投类动作 | 概念多源验证；30 天为经验起点 |
| 目标不明确 | 不输出通用降 ACoS 建议 | 事实：清库、推新、利润目标结论相反 |
| 缺少改前值或回滚条件 | 不执行写操作 | 事实：变更留痕与回滚要求 |

## 三、四个核心公式及其推导

### 3.0 记号

| 记号 | 含义 |
|---|---|
| `S` | 售价 |
| `C` | 产品成本 |
| `F` | FBA 配送费 |
| `R` | 平台佣金率 |
| `L` | 头程分摊 |
| `W` | 仓储及其他分摊 |
| `u` | 退货率 |
| `l` | 退货损失率 |
| `M` | 单位广告前贡献 |
| `G` | 目标单件净利 |
| `CVR` | 订单 ÷ 点击 |
| `T` | 目标 ACoS |

### 3.1 盈亏平衡 ACoS

**公式**

```text
M = S - C - F - S × R - L - W - S × u × l
盈亏平衡 ACoS = M ÷ S
```

> ⚠️ **实现与本文的已知差异**（2026-09-24 独立验收发现）：
> 当前代码实现（`state_builder.py` 的 `contribution()`）**没有扣除仓储/其他分摊 `W`**，
> 因此**代码算出的盈亏平衡 ACoS 会比本文公式偏乐观**（可承受的 ACoS 被高估）。
>
> 这是**实现缺口**，不是公式错误。使用代码算出的数值时，请把 `W` 的影响单独考虑，
> 或先补齐实现。相关记录见 [jev-ads-analysis](https://github.com/Wany-i/jev-ads-analysis) 仓库中的「09-踩坑与决策记录」之「实现与方法论脱节」条目。

**推导**

1. 一单不投广告时，能留下的贡献是 `M`。
2. 投广告以后，每获得一单可以承担的最大广告花费就是 `M`；超过 `M`，这一单由盈利变亏损。
3. ACoS 的定义是广告花费 ÷ 广告销售额。按一单口径，广告销售额约为 `S`。
4. 令广告花费 = `M`，再除以 `S`，得到 `M ÷ S`。

**事实依据**：`metrics.md` 给出该公式；Amazon 官方指南确认 break-even ACoS 与利润边际直接相关。**本项目额外扣头程、仓储/其他与退货损耗，是比官方通用口径更细的中国卖家成本实现。**

**口径提醒**：佣金率应按类目实际，不能用 15% 一刀切；退货率必须扣，否则会系统性高估可承受 ACoS；跨币种必须先统一币种。

### 3.2 目标 ACoS

**公式**

```text
目标 ACoS = (M - G) ÷ S
```

**推导**

1. 盈亏平衡线允许广告花掉全部 `M`，结果是单件净利为 0。
2. 如果希望单件至少留下 `G` 的净利，广告最多只能花 `M - G`。
3. 同样除以售价 `S`，得到日常调优的靶心。

**等价表达（策略姿态版）**

```text
目标 ACoS = 盈亏平衡 ACoS × 策略乘数
```

| 策略 | 乘数 | 含义 |
|---|---:|---|
| launch（推新品、买排名） | 1.40 × BE | 目标高于盈亏线，利润后置 |
| dominate（抢类目份额） | 1.15 × BE | 允许阶段性投入 |
| grow（自己养活自己） | 1.10 × BE | 小幅投入换增长 |
| maintain（维持） | ≤ 1.0 × BE | 不允许突破盈亏线 |

**事实依据**：利润公式来自 `metrics.md`；策略乘数来自第二轮验证中的 S10，并与 S5、S1、S8、O1 的相邻口径相互印证。

**推断**：当乘数 > 1 时，目标 ACoS 高于盈亏线，等价于把 `G` 设为负数，也就是明确接受阶段性亏损。必须在策略、预算上限和止损日期都明确时才能使用。

### 3.3 可接受 CPC（出价天花板）

**公式**

```text
可接受 CPC = S × CVR × 目标 ACoS
```

**推导**

1. 一次点击的期望广告销售额 = `售价 × 转化率`，即 `S × CVR`。
2. 目标 ACoS 表示“每 1 元广告销售额允许花多少广告费”。
3. 两者相乘，得到一次点击允许花费的上限。

**例**：售价 $40，CVR 8%，目标 ACoS 25% → `40 × 0.08 × 0.25 = $0.80`。当前 CPC $1.10 > $0.80，说明该词在当前转化与目标下结构性亏损，应该降价、优化转化，或重新判断目标，而不是靠加预算硬救。

**事实依据**：该公式在独立实现 S1 与 S5 中逐字一致；属于多源验证。

### 3.4 日预算下限

**公式**

```text
出 1 单所需点击数 ≈ 1 ÷ CVR
日预算下限 ≈ 预期 CPC × (1 ÷ CVR)
```

**推导**

1. 如果 CVR = 8%，平均约 `1 ÷ 0.08 = 12.5` 次点击出一单。
2. 若预期 CPC 为 `$1.00`，至少需要约 `$12.50` 才买得到这一单所需的点击量。
3. 预算低于这个量，广告可能在收集到可判断样本前就烧完。

**与倍数法的关系**

| 类型 | 倍数 | 等价假设 |
|---|---:|---|
| Broad seed | 10 × CPC | 约 CVR 10% |
| Auto / Phrase / Exact（stacked） | 8 × CPC | 约 CVR 12.5% |
| Exact（single） | 5 × CPC | 约 CVR 20% |

**事实依据**：倍数表来自 S10；中文来源 C9 独立给出“至少够买到一单所需点击量”的同构表述。两条路径在数学上收敛，属于多源验证。**最小日预算 $5 属于单一来源的实操值；若 CVR 明显低于 10%，8~10 倍不足，必须按 `1 ÷ CVR` 反算。**

### 3.5 不作为“四核心公式”的支撑公式

| 公式 | 用途 | 强度 |
|---|---|---|
| `TACoS = 广告花费 ÷ 总销售额` | 判断广告对整店的影响、自然位是否被蚕食 | 事实公式；阶段区间为参考值 |
| `动态点击阈值 = 1 ÷ CVR` | 判断点击数是否足够进入重点排查 | 多源验证 |
| `重点排查线 ≈ 2.5~3 × 出单所需点击` | 避免因短期零单误否 | 中文独立复现，量化倍数来自单一来源 |
| `新出单词占比 = 本期新出单词数 ÷ 本期全部出单词数` | 衡量新增需求与探索效率 | 事实公式；实测数字为 C6 单一来源 |
| `新词效率倍数 = 新词 CVR ÷ 历史词 CVR` | 判断新词是否优于存量词 | 事实公式；实测数字为 C6 单一来源 |

## 四、判据表：每类动作靠什么触发

> 下表只列“触发规则”。具体层级、前置门控和回滚条件仍以 `diagnosis.md`、`actions.md` 为准。

| 动作族 | 主要触发 | 必须同时满足 / 禁止条件 | 证据强度 |
|---|---|---|---|
| 否定精确 | 点击超过 `1 ÷ CVR`，花费 ≥ 3× 目标 CPC，0 单 | 绝对下限 5 次点击；词义确实不匹配；连续观察；强相关词不否定 | 多源验证（V2/V24/V28） |
| 否定词组 | 一类错误词根持续带来无关流量 | 先小批量；观察曝光下降是否超过 40% | 多源验证 |
| 降价 | ACoS > 盈亏平衡线，点击 ≥ 20 | 单次 -20%~-30%；盈亏线优先于目标线；学习期不动 | 多源验证（V3/V4） |
| 微调降价 | ACoS 位于目标与盈亏线之间 | 单次 -10%~-15%；观察一个周期 | 多源验证 |
| 提价 | ACoS ≤ 目标 × 0.8 且曝光受限 | 库存充足；有足够样本；提价 +10%~+20% | 多源验证 |
| 收割 / 迁 Exact | 转化速率 ≥ 1~2 单/周 | ACoS 不决定是否收割；1~2 单/周 → stacked，≥2 单/周 → 独立 Exact；原位置否定精确 | 方法论级多源验证（V5/V17） |
| 收割闭环 | 优质词同时高点击、高转化、低 ACoS、低 CPC | 广告侧单独投放；自然侧埋入 Search Term 与五点描述 | 单一来源（C29） |
| 拆组 / 收敛 | 单组 > 50 词；混品类、价格带或 ROAS；同词在 3+ 活动 | 先拆结构，再解释搜索词数据 | 部分官方，部分经验起点 |
| 加预算 | 预算烧穿且 ACoS ≤ 目标 | 单次 +20%~+30%；库存充足；不能以加预算替代止损 | 多源验证 |
| 降预算 / 重分配 | 活动低效且短期无法修复；预算与收入占比不匹配 | 单次批量变更 ≤ 对象总量 20% | 多源验证 |
| 广告位调整 | 看该位 ACoS 相对 BE 的倍数，而非 CVR 倍数 | TOS 1.15×/0.7×；ROS 1.0×/0.7×；PP 1.4×且无加价档；必须有订单/销售额证据 | 框架多源；精确倍数主要来自 S10 |
| 分时 | 某时段 ACoS 显著高于均值且花费占比 ≥ 15% | 降低该时段出价与预算；不要暂停；全天平稳不做 | 多源验证（C29 等 5 处支持“不要暂停”） |
| 暂停 / 关停 | 连续 14 天 0 单且花费 ≥ 10× 目标 CPC；或降价后仍越线 | 保留数据；不要用于分时；不要一次性关停 | 多源验证 |
| 库存门控 | 库存 < 30 天销量 | < 30 天停止加投；< 14 天逐步收缩；< 7 天关 Auto/广泛；断货保留品牌词/Exact 低预算 | 概念多源；30/14/7 天为经验起点 |
| 学习期门控 | 新活动或大改后 | < 3 天禁止；保守默认 7 天；多次调整会重置/延长学习 | 机制多源；天数经验起点 |

## 五、分动作门控阈值的逻辑

### 5.1 先过门控，再比阈值

| 门控 | 问题 | 失败后的动作 |
|---|---|---|
| G0 目标门 | 目标是利润、排名、清库还是冲量？ | 不产出通用建议 |
| G1 财务门 | 盈亏平衡 ACoS 和目标 ACoS 是否已算？ | 先补成本与目标，不调价 |
| G2 样本门 | 点击是否达到 `1 ÷ CVR`，至少 5/10/20 的可判断线？ | 进入观察名单，不执行 |
| G3 因果门 | 问题是流量、Listing、价格、库存，还是投放？ | 先修对应环节，不调广告 |
| G4 状态门 | 是否学习期、大促、断货、预算耗尽？ | 暂停或延期执行 |
| G5 执行门 | 是否有改前值、影响预估、批量 ≤ 20%、回滚条件？ | 不进入写流程 |

### 5.2 为什么不同动作的阈值不同

| 设计 | 原因（推断） | 事实锚点 |
|---|---|---|
| 否定用 `1 ÷ CVR`，不用固定 10 次 | 不同转化率下，10 次对不同商品的证据含义不同 | V28：8% CVR 对应 12~13 次，2.5~3 倍才重点排查 |
| 降价用 20 次点击 | 价格是可逆但会直接影响流量，需要更保守样本 | V3：20 次点击获多源支持 |
| 单次降价 -20%~-30% | 一次到位容易打穿流量，分档可观察边际 | V4：多个实现落在该交集 |
| 广告位看 ACoS/BE 倍数 | 位置不是独立 KPI；TOS 买排名，ROS 意图较弱，PP 只应收紧 | V11：位置容忍带不同 |
| 广告位加价一次最多当前值的 25% | 避免把位置溢价从修饰符变成主出价 | 事实：幅度按当前值百分比 |
| 预算加 20%~30% | 预算变化会改变全天展示与学习，需给系统稳定窗口 | 多源验证 |
| 批量变更 ≤ 20% | 自动化的最大风险是把单点错误批量放大 | 多源验证 |
| 观察 3~5 天、结构看 14~30 天 | 日常波动与结构变化的时间尺度不同 | C22 + S4 等 |
| 学习期不调 | 频繁调整会重置/延长学习，不只是“前几天没数据” | V6/V20 |
| 分时不暂停 | 暂停破坏连续性，可能降低广告权重与质量得分 | 第六轮 C29 及 5 处相邻支持 |

### 5.3 阈值不是教条

`diagnosis.md` 明确写着“阈值是起点不是教条”。落地时必须先用本品类、本价格带、本 ASIN 的历史 CVR 校准，再用可接受 CPC 公式复核。**多源验证只能证明“这个方向和方法有出处”，不能证明某个数字对每个账号都是最优值。**

## 六、P0 / P1 / P2 分级

### 6.1 定义

| 级别 | 目标 | 典型动作 | 时间要求 |
|---|---|---|---|
| **P0** | 止血 | 否掉明确浪费词；处理越线花费；断货前收缩；停止无效活动 | 立即或本周期内 |
| **P1** | 提效 | 降价、结构拆并、收割、预算重分配、否词后的迁移 | 本周期调整并观察 |
| **P2** | 增长 | 提预算、提价、测试 TOS、新增 Exact、开发新词 | 下周期或条件满足后 |

### 6.2 分级不是“金额大就优先”

**推断**：优先级取决于“风险是否继续扩大 + 动作是否可逆 + 证据是否足够 + 是否阻塞其他动作”。

| 情形 | 分级变化 | 理由 |
|---|---|---|
| 越线花费持续累积 | P1 → P0 | 每多跑一天都在扩大亏损 |
| 相关但 0 单 | 不进入否定 P0 | 可能是转化问题，误否会砍掉有效流量 |
| 高效词但预算受限 | P2 或 P1 | 增长机会，不应抢占止血资源 |
| 库存 < 7 天仍在加投 | 立即 P0 | 断货比少卖更伤排名与评论 |
| 大促当天发现结构问题 | 延后到 P2 | 大促期间做结构变更风险更高 |
| 证据样本不足 | 观察名单，不给 P0/P1 | 低样本动作可能只是噪声 |

### 6.3 输出纪律

每条动作必须写全：**对象 → 现值 → 目标值 → 依据 → 预期影响 → 风险/回滚条件**。P0 可以更短，但不能缺依据；P1/P2 必须带观察周期和复查日期。

## 七、一页速查

| 主题 | 固定动作 |
|---|---|
| 先算什么 | 盈亏平衡 ACoS → 目标 ACoS → 可接受 CPC → 日预算下限 |
| 先查什么 | 有 SQP 先查份额断崖；无 SQP 先声明缺层 |
| 再查什么 | 店铺/账户 → 活动 → 结构 → 搜索词 → 广告位 → 时段 |
| 大促怎么办 | 用第 7 层反向解读，不做日常结构判断 |
| 找增量怎么办 | 先完成止血与结构稳定，再用第 8 层分析新词 |
| 何时不动 | 学习期、样本不足、大促高峰、库存不足、目标不明 |
| 如何排序 | P0 止血、P1 提效、P2 增长 |
| 如何执行 | 只读默认；写操作逐条确认；批量 ≤ 20%；改前值 + 回滚条件 |

## 八、边界与未验证项

| 条目 | 状态 |
|---|---|
| SQP 份额断崖定位法 | **经验起点**：基于官方 SQP 字段定义自建，未获外部原文印证 |
| 词簇法完整流程 | **待补 / 未验证**：仅取得摘要片段，尚未拿到完整方法 |
| 具体阈值是否适用于所有类目 | 未验证：来源明确要求按本品类与自身历史校准 |
| 精确权重机制与 Amazon 内部排序 | 未验证：外部来源只能给出机制性解释，不能证明内部算法 |
| `1 ÷ CVR` 之外的 2.5~3 倍重点排查线 | **单一来源**：来自 C23 |
| 学习期 7 天、库存 30 天 | **经验起点**：机制有多源支持，具体天数为保守默认 |
| 日预算最小 $5、Auto 75%、TOS/ROS/PP 精确倍数 | **精确数值单一来源或来源间无共识**：方向可参考，数值需自校准 |
| 控制实验 / A-B 验证 | **未验证**：现有证据是多来源文献与实现互证，不是亚马逊内部实验 |

> **一句话边界**：这套方法论能证明“为什么这样设计、每条阈值来自哪里、什么时候不该用”；它不能证明“某个数字对所有账号都正确”。
